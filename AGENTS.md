# Инструкции для Codex

## Начало каждой сессии

1. Полностью прочитай `README.md`.
2. Полностью прочитай `docs/session-handoff.md`.
3. Загружай остальные документы только по необходимости:
   - позиционирование и постоянный контекст — `docs/project-context.md`;
   - go-to-market стратегия — `docs/go-to-market-strategy.md`;
   - проверка провайдеров — `docs/provider-scorecard.md`;
   - проверка рынка и источники — `docs/market-validation.md`;
   - текущий эксперимент — `docs/30-day-validation-plan.md`;
   - история решений — `docs/decision-log.md`.
4. Перед изменениями выполни `git status --short --branch` и сохрани чужие правки.

## Рабочий принцип

- Чётко разделяй факты, гипотезы, решения и результаты экспериментов.
- Не выдавай публичные условия партнёрских программ за гарантированные:
  коммерческие условия должны подтверждаться письменным договором.
- Для данных, способных измениться, используй актуальные первичные источники
  и сохраняй ссылку вместе с датой проверки.
- Не расширяй нишу без явного решения пользователя.
- Не отправляй сообщения, заявки, письма и формы внешним лицам без прямого
  разрешения пользователя на конкретную кампанию.
- Не придумывай опыт, клиентов, партнёров, объёмы или квалификацию пользователя.
- Общайся с пользователем по-русски; англоязычные коммерческие тексты давай
  вместе с понятным русским смыслом.

## Приватность

Храни только сведения, необходимые для выполнения проекта. Не записывай в Git:

- возраст, домашний адрес, точную локацию и планы переезда;
- личный уровень дохода, семейные сведения и персональные документы;
- название работодателя, закрытые условия работы и внутренние контакты;
- имена клиентов без рабочей необходимости и разрешения;
- API-ключи, пароли, seed phrases, wallet credentials и access tokens;
- закрытые договоры, необработанные KYC-файлы и банковские реквизиты.

Профессиональные вводные описывай обезличенно: компетенции, доступный ресурс,
границы проекта и подтверждённые результаты. Перед каждым push проверяй diff
на персональные данные и секреты.

## Комплаенс и границы

Проект работает только с реальными юридическими лицами и деятельностью,
допустимой для заявленной лицензии и целевого рынка.

Не помогай:

- обходить KYC, AML, санкционные или лицензионные требования;
- скрывать реальный MCC, географию, домены или бенефициаров;
- использовать подставные компании, документы или merchant accounts;
- подключать нелицензированный gambling там, где лицензия обязательна;
- строить схемы транзита, обнала, отмывания или мошеннических chargebacks.

Допустимая зона: законный high-risk underwriting, лицензированный iGaming,
crypto processing у провайдеров с проверяемым статусом, chargeback prevention
и dispute management.

## Обновление контекста

После значимой рабочей сессии:

1. Обнови дату и блоки в `docs/session-handoff.md`.
2. Запиши подтверждённые числа и результаты, а не впечатления.
3. При принятии или отмене направления добавь запись в `docs/decision-log.md`.
4. Не переписывай прошлые записи задним числом; добавляй новую запись.
5. Не сохраняй в Git секреты, персональные данные или закрытые материалы.

## Git

- Основная ветка: `main`.
- Коммиты должны быть атомарными и иметь понятный префикс:
  `docs:`, `research:`, `experiment:`, `chore:`.
- Перед коммитом проверь staged diff и отсутствие секретов.
- Перед началом работы на другом устройстве выполняй `git pull --ff-only`.

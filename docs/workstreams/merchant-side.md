# Поток Merchant Side

Обновлено: 2026-08-02.

## Миссия

Подготовить один узкий, проверяемый merchant experiment, который можно запустить
сразу после появления двух Active providers.

До provider gate новые системные merchant-касания не отправляются.

## Очередь задач до provider gate

1. Подготовить rubric выбора ICP из фактического provider coverage.
2. Создать checklist публичных merchant triggers.
3. Подготовить структуру безопасного pipeline без закрытых данных в Git.
4. Подготовить qualification checklist для 15-минутного discovery call.
5. Написать три черновика outreach под разные возможные triggers:
   crypto rail, backup processing и dispute pressure.
6. Подготовить две follow-up формулы без ложной срочности и обещаний.
7. Сформировать правила no-fit и обязательные данные до introduction.

Эти материалы являются заготовками. Финальный вариант выбирается только после
того, как Provider Side передаст реальное coverage.

## Очередь задач после provider gate

1. Зафиксировать один тип оператора, license group, 2–3 GEOs, продукт,
   volume band, trigger и decision-maker role.
2. Проверить первые 40–50 компаний на наблюдаемый trigger.
3. После прямого разрешения пользователя запустить персонализированные касания.
4. Сделать follow-up через 3–5 и 8–12 рабочих дней.
5. Довести цикл до 80–100 новых касаний и минимум четырёх discovery calls.
6. Передать только квалифицированную и защищённую introduction.

## Definition of done

Поток подтверждает первый merchant experiment, когда получены:

- 80–100 персонализированных новых касаний;
- минимум 8 содержательных ответов;
- минимум 4 discovery calls;
- минимум 2 подтверждённые платёжные потребности;
- минимум 1 защищённая introduction;
- минимум 1 opportunity в underwriting или onboarding.

Это внутренние пороги эксперимента, а не рыночные гарантии.
